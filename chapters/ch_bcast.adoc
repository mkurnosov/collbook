== Широковещательная передача

В стандарте MPI определено два типа операций широковещательной рассылки сообщений из выделенного _корневого_ процесса (root) всем членам коммуникатора: Bcast и Scatter. В операции Bcast корень передает всем одно и то же сообщение, содержимое одного буфера. В случае Scatter корневой процесс рассылает всем персональные сообщения. Для Scatter также определена операция Scatterv, поддерживающая рассылку сообщений разных размеров.

=== Операция Bcast

В операции Bcast корневой процесс latexmath:[root] передает latexmath:[count] элементов типа latexmath:[datatype] всем процессам коммуникатора latexmath:[comm].

[source,c]
----
MPI_Bcast(buf, count, datatype, root, comm)
----

В корневом процессе latexmath:[buf] выступает в качестве буфера отправки, а в некорневых процессах – буфером для приема сообщения. Всем процессам рассылается одинаковое сообщение, поэтом данную операцию также называют _неперсонифицированной широковещательной передачей_ (non-personalized broadcast). В отечественной литературе закрепилось альтернативное название – _трансляционный обмен_  <<bib-khor2010,[58]>>,<<bib-khor78,[2]>>,<<bib-korneev85,[3]>>,<<bib-Monakhov2000,[4]>> .

Для алгоритмов операции Bcast известна нижняя граница времени выполнения  <<bib-Sanders2009-two-tree,[28]>>,<<bib-Hoefler2014-Bcast,[59]>> :

[latexmath]
++++
t_{{Bcast}} \ge \min\{\lceil\log_2 p\rceil\alpha, m\beta\},
++++
где latexmath:[m = count \cdot \mathrm{sizeof}(datatype).]

Рассмотрим основные алгоритмы реализации операции Bcast. Мы будем двигаться от простейших к более сложным и эффективным. Нас будут интересовать только алгоритмы, которые в явном виде используют операции Send/Recv для выполнения отдельных шагов коллективной операции. Мы осознано не будем рассматривать аппаратно реализованные алгоритмы (например, NVIDIA SHARP, Cray Aries Collective Engine), так как они эксплуатируют аналогичные идеи. Также мы не будем рассматривать алгоритмы для фиксированных сетевых топологий (latexmath:[k]D-торов, многомерных кубов, многокаскадных сетей) и иерархические методы, которые в пределах многопроцессорного узла локализуют обмены между процессами через его общую память. Все перечисленные специальные методы в своей основе опираются на базовые алгоритмы, которые и являются предметом нашего рассмотрения.

Значительная часть известных алгоритмов основана на логической организации процессов в деревья различных видов. Зная свой номер latexmath:[rank] каждый процесс определяет номера процессов с которыми он выполняет коммуникации. В подавляющем большинстве случаев такие вычисления выполняется за константное время относительно latexmath:[p]. Мы будем отдельно обсуждать ситуации когда время вычисления положения процесса в дереве функционально зависит от latexmath:[p]. При анализе времени выполнения алгоритмов будем подсчитывать затраты на выполнение операций Send и Recv.

=== Алгоритмы с линейной сложность

Классическими представителями алгоритмов с линейной зависимостью времени выполнения от числа процессов являются _линейный алгоритм_ (linear broadcast, flat tree broadcast), _конвейерный алгоритм_ (pipeline, chain) и их комбинация – _алгоритм параллельных цепочек_ (latexmath:[k]-chain broadcast).

В _линейном алгоритме_ корневой процесс latexmath:[root] последовательно передает сообщение latexmath:[p - 1] процессам. Ниже приведен его псевдокод. Считаем, что операции Send и Recv блокируют выполнение алгоритма до завершения передачи и приема сообщения.

[source,c]
----
algorithm BcastLinear(buf, count, type, root)
  if rank = root then
    for (i = 0; i < p; i++)
      if i != root then
        Send(buf, count, type, i)
    end for
  else
    Recv(buf, count, type, root)
  end if
end algorithm
----

.Рис. 3.1. Временная диаграммы выполнения линейного алгоритма операции Bcast для 4 процессов с корнем в 0.
[[fig:bcast_linear]]
image::bcast-linear.svg[width=40%]

Корневой процесс 0 выполняет последовательную передачу трех сообщений. Каждая передача длится latexmath:[\alpha + m\beta] единиц времени. Прямоугольники с операциями отражают время на коммуникации, в них не включено время ожидания поступления сообщения. Например, процесс 2 ожидает в операции Recv начала приема latexmath:[\alpha + m\beta] единиц времени, пока корень не завершит передачу сообщения процессу 1. Аналогично, в процессе 3 время ожидания составляет latexmath:[2(\alpha + m\beta)]. Время выполнения алгоритма определяется наибольшим из времен выполнения процессов, которое приходится на корневой процесс и процесс с номером latexmath:[p - 1]. В общем случае время выполнения линейного алгоритма

[latexmath]
++++
t_{{Linear}} = (p - 1)(\alpha + m\beta).
++++

В _конвейерном алгоритме_ Bcast процессы по цепочке, начинаю с корневого, передают друг другу сообщение. Ниже приведен псевдокод алгоритма, в котором учитывается возможность назначения корневым любого процесса.

[source,c]
----
algorithm BcastPipeline(buf, count, type, root)
  next = (rank + 1) % p
  if rank = root then            // Первый процесс в цепочке
    Send(buf, count, type, next)
  else
    prev = (rank - 1 + p) % p
    Recv(buf, count, type, prev)
    if next != root then
      Send(buf, count, type, next)
  end if
end algorithm
----

На <<fig:bcast_pipeline,рис. 3.2>> приведен пример для четырёх процессов. Первым выполнение завершает корневой процесс, а последним – процесс latexmath:[(root - 1 + p) \mathbin{\%} p] в конце цепочки, время которого и определяет итоговое время алгоритма

[latexmath]
++++
t_{{Pipeline}} = (p - 1)(\alpha + m\beta).
++++

Зададимся вопросом – как можно сократить время выполнения линейных алгоритмов, как построить более быстрый алгоритм Bcast? Очевидная идея – реализовать одновременную передачу сообщений в нескольких цепочках процессов.

=== Алгоритм параллельных цепочек

Алгоритм _параллельных цепочек_ (latexmath:[k]-chain) организует latexmath:[p] процессов в latexmath:[k] цепочек, где latexmath:[k] – это входной параметр алгоритма. На первом шаге корень передает сообщение лидеру первой цепочки, на втором шаге корень передает сообщение лидеру второй цепочки и одновременно с этим лидер первой цепочки передает сообщение своему следующем процессу.

[.text-center]
.Рис. 3.3. Диаграммы выполнения алгоритма с тремя параллельными цепочками для latexmath:[p=20] процессов.
[[fig:bcast_kchain_p20_k3]]
image::bcast-kchain-p20-k3.svg[width=40%]

После шага latexmath:[k] лидеры всех цепочек получили сообщение от корня и по всем цепочкам выполняется параллельная передача сообщений – это ключевая идея алгоритма. В каждую цепочку входит по latexmath:[(p-1)/k] процессов. Если latexmath:[p-1] не делится без остатка на latexmath:[k], то остаток отделения, latexmath:[(p-1) \mathbin{\%} k] процессов, распределяются по первым latexmath:[(p-1) \mathbin{\%} k] цепочкам – в каждую добавляется по одному процессу. Отметим, что добавлять процессы из остатка целесообразно в первые цепочки, так как это приводит к меньшему увеличению времени выполнения алгоритма по сравнению с добавлением в последние цепочки. Предлагаем читателю самостоятельно проверить это утверждение.

На <<fig:bcast_kchain_p20_k3,рис. 3.3>> приведен пример для latexmath:[p=20] процессов, которые организованы в latexmath:[k=3] параллельные цепочки по 6 процессов. В первую цепочку включен дополнительный процесс из остатка от деления 19 на 3. Числа над дугами – это номер шага, на котором выполняется передача. Например, процесс 7 получит сообщение в момент времени latexmath:[7(\alpha+m\beta)], а процесс 19 в latexmath:[8(\alpha+m\beta)]. Время выполнения алгоритма определяется временем завершения latexmath:[(p-1)/k - 1] передач в последней цепочке:

[latexmath]
++++
t_{{k-chain}} = k(\alpha+m\beta) + \left( \left\lfloor\frac{p-1}{k}\right\rfloor - 1\right)(\alpha+m\beta).
++++
Нетрудно заметить, что время выполнения алгоритма параллельных цепочек линейно зависит от числа процессов, как и в предыдущих алгоритмах. Открытым остается вопрос о выборе значения latexmath:[k]. На практике для заданной вычислительной системы можно экспериментально определить оптимальные значения latexmath:[k] для различных latexmath:[p] и latexmath:[m]. Рассмотрим альтернативный подход, который лежит в основе следующего алгоритма, – это теоретическое нахождение оптимального числа цепочек (в рамках нашей модели latexmath:[m], latexmath:[p], latexmath:[\alpha], latexmath:[\beta]).

Для построения алгоритма _с оптимальным числом параллельных цепочек_ (latexmath:[k]-opt-chain) из полученного выражения latexmath:[t_{{k-chain}}] найдем число latexmath:[k] цепочек, при котором он работает за минимальное время. Для этого найдем производную функции по latexmath:[k] и приравняем её к нулю

[latexmath]
++++
\frac{\partial}{\partial k}\left( k(\alpha+m\beta) + \left(\frac{p-1}{k}-1\right)(\alpha+m\beta) \right) = 1 - \frac{p-1}{k^2} = 0.
++++
Отсюда оптимальное число цепочек latexmath:[k^{*} = \sqrt{p-1}]. Подставим полученное значение latexmath:[k^{*}] в выражение для времени latexmath:[t_{{k-chain}}] и получим время работы алгоритма с оптимальным числом цепочек:

[latexmath]
++++
t_{{k-chain-opt}} = (2\sqrt{p-1} - 1)(\alpha+m\beta).
++++
Этот алгоритм имеет степенную зависимость времени работы от числа процессов (показатель степенной функции latexmath:[\frac{1}{2}]). Время выполнения с увеличением latexmath:[p] растет медленнее чем у алгоритмов с линейным числом шагов. На <<fig:bcast_kchain_k,рис. 3.4>> показана зависимость количества шагов алгоритма (операций передачи), от числа latexmath:[k] цепочек для 64, 128 и 256 процессов. На кривых показаны значения latexmath:[k_{64}], latexmath:[k_{128}] и latexmath:[k_{256}], при которых достигается минимум времени выполнения алгоритма для соответствующего числа процессов.

Алгоритм завершается за 5 шагов. Нетрудно заметить, что передача сообщения в следующей цепочке завершается на один шаг позже текущей или за такое же время. Это связано с тем, что на доставку сообщения в очередную цепочку корневому процессу требуется отдельный шаг. Чтобы время завершения операций в цепочках не превышало времени первой, каждая следующая цепочка должна быть на один процесс короче предыдущей. Эта базовая идея алгоритма _параллельных цепочек переменной длины_. Длины цепочек образуют убывающую арифметическую прогрессию. В первой цепочке latexmath:[k] процессов. Итоговое время выполнения алгоритма – 4 шага, что быстрее алгоритма с тремя параллельными цепочками (<<fig:bcast_kchain_p11_k3,рис. 3.5>>).

.Рис. 3.6. Диаграммы выполнения алгоритма с переменным числом цепочек (latexmath:[k=4], latexmath:[p = 11]).
[[fig:bcast_kchain_p11_tri]]
image::bcast-kchain-p11-tri.svg[width=25%]

Найдем для заданного числа latexmath:[p] процессов число latexmath:[k] цепочек переменной длины. По цепочкам распределены latexmath:[p-1] процессов: latexmath:[k] процессов в первой цепочке, latexmath:[k-2] – во второй, latexmath:[\ldots], в последней – один процесс. Из выражения для суммы latexmath:[n] элементов арифметической прогрессии получаем равенство:

[latexmath]
++++
p - 1 = \frac{k^2 + k}{2}, \quad\quad k^2 + n - 2(p-1) = 0.
++++
Откуда находим значение latexmath:[k]:

[latexmath]
++++
k = \frac{\sqrt{8(p-1) + 1} - 1}{2}.
++++
Если latexmath:[p-1] не делится без остатка на latexmath:[k], то остаток отделения, latexmath:[(p-1) \mathbin{\%} k] процессов, распределяются по первым latexmath:[(p-1) \mathbin{\%} k] цепочкам – в каждую добавляется по одному процессу. Время выполнения алгоритма определяется временем цепочки latexmath:[k]:

[latexmath]
++++
t_{{k-chain-var}} = \left\lceil (\sqrt{8(p-1) + 1} - 1)/2 \right\rceil (\alpha+m\beta).
++++
Этот алгоритм имеет степенную зависимость времени работы от числа процессов, как и алгоритм с оптимальным числом параллельных цепочек. На <<fig:bcast_algs_linear,рис. 3.7>> показана зависимость времени выполнения алгоритмов от числа процессов, а также нижняя граница latexmath:[\log_2p] числа шагов операции Bcast.

=== Алгоритм бинарного дерева

Алгоритм выстраивает процессы в _бинарное дерево_ (binary tree), по которому от корня к листам передается сообщение. Ключевая идея алгоритма – параллельная передача данных в левом и правом поддеревьях корня. Каждый процесс вычисляет свое положение в дереве, номер latexmath:[parent] родительского процесса и номера дочерних latexmath:[left], latexmath:[right], только на основе своего номера latexmath:[rank] и общего числа latexmath:[p] процессов. Конкретный алгоритм вычисления latexmath:[parent], latexmath:[left], latexmath:[right] определяется формой бинарного дерева и способом нумерации узлов – распределением latexmath:[p] процессов по дереву. На практике распространение получили две формы деревьев для операции Bcast: завершенное бинарное дерево (complete binary tree) и бинарное дерево сбалансированное по число узлов в поддеревьях. Ниже мы рассмотрим их по отдельности.

Нумерацию узлов дерева можно задать разными способами. Эта процедура должна быть нетрудоёмкой и позволять каждому процессу вычислять свое положение за разумное для практики время – желательно за константное время, которое не зависит от числа процессов. Можно выделить следующие способы нумерации узлов:

* в порядке прямого обхода дерева (pre-order);
* в порядке симметричного обхода (in-order);
* в порядке обратного обхода (post-order);
* позиция каждого процесса явным образом вычисляется из его номера latexmath:[rank].

_Завершенное бинарное дерево_ (complete binary tree) – бинарное дерево, в котором все уровни заполнены, возможно за исключением последнего, который заполняется слева направо. Зная свой номер latexmath:[rank] каждый процесс за константное время вычисляет номера родительского узла latexmath:[parent], левого latexmath:[left] и правого latexmath:[right] дочерних процессов, если они присутствуют:

[latexmath]
++++
left = 2 \cdot rank + 1, \quad right = 2 \cdot rank + 2, \quad parent = \lfloor (rank - 1)/ 2\rfloor.
++++
На <<fig:bcast_cmpl_bin_tree_p13,рис. 3.8>>._а_ приведен пример завершенного бинарного дерева для latexmath:[p=13] процессов. Последним сообщение получает самый правый листовой процесс 12 на шаге 5. В этом примере самый левый лист имеет высоту больше чем самый правый, поэтому такое дерево будем называть _левосторонним деревом_.

Для операции Bcast используют левосторонние деревья. Потому, что корневому процессу целесообразно на первом шаге передавать сообщение в поддерево с б__о__льшим числом узлов. Это обеспечит завершение операции Bcast во втором поддереве за время не превосходящее время в поддереве c б__о__льшим числом узлов. Например, на <<fig:bcast_cmpl_bin_tree_p13, рис. 3.8>>._б_ показано правостороннее дерево для 13 процессов. Операция Bcast в нем завершается за 6 шагов, что на 1 шаг больше чем в левостороннем дереве.

Как было показано выше, алгоритм заканчивает работу, когда самый правый листовой процесс получает сообщение. Для простоты анализа оценим время выполнения алгоритма завершенного бинарного дерева, для случая когда все листовые узлы находятся на одной высоте, а все не листовые процессы имеют два дочерних узла – форма _совершенного бинарного дерева_ (perfect binary tree). В этом случае время выполнения операции Bcast определяется временем правого листа:

[latexmath]
++++
t_{{BinTree}} = 2h(\alpha+m\beta) = 2\left\lfloor\log_2 p\right\rfloor (\alpha+m\beta),
++++
где latexmath:[h] – высота самого правого дочернего листа. Если завершенное дерево имеет форму отличную от совершенной, время выполнения операции Bcast не превосходит latexmath:[t_{{BinTree}}].

Из выражения latexmath:[t_{{BinTree}}] видно, что время выполнения алгоритма бинарного дерева логарифмически зависит от числа процессов. В то же время, оно в два раза больше нижней границы времени Bcast по латентности (константа перед latexmath:[\alpha]) и в latexmath:[2\log_2 p] раз больше нижней границы по пропускной способности (константа перед latexmath:[\beta]).

Нетрудно обобщить алгоритм путем перехода к алгоритму _latexmath:[k]-ичного завершенного дерева_ (latexmath:[k]-ary complete tree), в котором каждый узел имеет не более latexmath:[k] дочерних процессов. Время выполнения такого алгоритма будет определяться временем самого правого листа (<<fig:bcast_perf_ktree,рис. 1.9>>):

[latexmath]
++++
t_{{KTree}} = kh(\alpha+m\beta) = k\left\lfloor\log_k p\right\rfloor (\alpha+m\beta).
++++

[.text-center]
.Рис. 3.9. Совершенные бинарные деревья Bcast: бинарное дерево, тернарное дерево и latexmath:[k]-ичное дерево высоты latexmath:[h].
[[fig:bcast_perf_ktree]]
image::bcast-perf-tree-k3.svg[width=80%]

Ниже приведен псевдокод обобщенного алгоритма. Обратим внимание на то, что корнем latexmath:[root] операции может быть выбран любой процесс. В приведенных ранее формулах для вычисления положения процесса в завершенном бинарном дереве предполагается что latexmath:[root = 0]. Мы можем ввести новую нумерацию процессов (смещенную, shifted), в которой корень будет иметь номер 0, вычислить положения каждого узла с использованием ранее рассмотренных формул, а при выполнении операции осуществить обратный переход к исходной нумерации. Процесс получает новый номер latexmath:[srank = (rank - root + p) \mathbin{\%} p] циклическим сдвигом. Обратный переход latexmath:[rank = (srank + root) \mathbin{\%} p].

[source,c]
----
algorithm BcastKTree(buf, count, type, root)
  srank = (rank - root + p) % p  // Переход к root = 0
  for (i = 0; i < k; i++)        // Вычисление дочерних процессов
    child[i] = k * srank + i + 1
  end for
  if rank != root then
    sparent = (srank - 1) / 2    // Лист или внутренний узел
    Recv(buf, count, type, (sparent + root) % p)
  end if
  for (i = 0; i < k; i++)
    if child[i] < p then
      Send(buf, count, type, (child[i] + root) % p)
  end for
end algorithm
----

Время выполнения алгоритма latexmath:[k]-ичного дерева в latexmath:[k] раз больше нижней границы по латентности и в latexmath:[k\log_k p] раз больше нижней границы по пропускной способности.

Для реализации Bcast можно использовать latexmath:[k]-ичные деревья и других видов. Например, _дерево сбалансированное по числу узлов_ (<<fig:bcast_balanced_bin_tree_p13,рис. 1.10>>). В левом и правом поддеревьях число процессов отличается не более чем на единицу. Время выполнения Bcast завершается за 5 шагов, как и в случае завершенного бинарного дерева. В таком дереве процесс latexmath:[rank] находится на уровне latexmath:[l = \lfloor \log_k (rank + 1) \rfloor], а его дочерние узлы имеют номера:

[latexmath]
++++
rank + k^l \cdot 1, \quad rank + k^l \cdot 2, \quad \ldots, \quad rank + k^l \cdot k.
++++
Вычисление позиции процесса в сбалансированном по числу узлов дереве связно с вычислением логарифмов и возведением в степень, на это может потребоваться порядка latexmath:[O(\log p)] единиц времени. Этот алгоритм реализован в библиотеке Open MPI (компонент coll/base).

[.text-center]
.Рис. 3.10. Бинарное дерево Bcast сбалансированное по числу узлов для latexmath:[p = 13] процессов.
[[fig:bcast_balanced_bin_tree_p13]]
image::bcast-balanced-bin-tree-p13.svg[width=30%]

Заметим, что два дерева Bcast с одной формой и разной нумерацией узлов могут приводить как разному времени на целевой системе. Это связано с тем, как процессы распределены по процессорам вычислительной системы (process mapping, task affinity). Например, возможна ситуация, при которой родитель и дочерний узел в дереве размещены на значительном расстоянии в топологии системы, например, на процессорах разных вычислительных узлов. Учет распределения процессов по процессорам системы и топологии сети – это задача архитектурно-ориентированных алгоритмов, рассмотрение которые выходят за тематические рамки этой книги.

Вернемся к вопросу о выборе оптимального значения latexmath:[k] для завершенного бинарного дерева операции Bcast.

=== Алгоритм оптимального latexmath:[k]-ичного дерева

Из выражения для latexmath:[t_{{KTree}}] найдем оптимальную latexmath:[k^*] степень дерева, при которой время выполнения операции Bcast минимально.

[latexmath]
++++
\frac{\partial}{\partial k} \left( k\log_kp(\alpha+m\beta) \right) = \frac{\ln p\ln k - \ln p}{\ln^2 k} = 0,
++++

[latexmath]
++++
k^* = e \approx 2.7183.
++++
Таким образом тернарное дерево (latexmath:[k = 3]) является оптимальным в рассматриваемой latexmath:[\alpha]-latexmath:[\beta] модели. На <<fig:bcast_ktree-time, рис. 3.11>> показана зависимость количества шагов алгоритма от степени latexmath:[k] дерева для различного числа процессов.

[.text-center]
.Рис. 3.11. Зависимость количества шагов алгоритма от степени latexmath:[k] дерева.
[[fig:bcast_ktree-time]]
image::bcast-ktree-time.svg[bcast-ktree-time]

Полученный алгоритм все еще не достигает нижней границы времени выполнения Bcast. Построим более эффективный алгоритм. Обратим внимание на то, что в бинарном дереве степень каждого узла фиксирована, она не зависит от числа потомков. Чтобы время завершения операций в поддеревьях корня не превышало времени в первом поддереве, надо чтобы каждое следующее поддерево было на единицу ниже предыдущего (содержало меньше узлов). Эта идея лежит в основе алгоритма биномиального дерева.

[[bcast_bmtree]]
=== Алгоритм биномиального дерева

В данном алгоритме процессы выстраиваются в биномиальное дерево. Каждое _биномиальное дерево_ latexmath:[B_k] (binomial tree) порядка latexmath:[k] – это рекурсивно определенное корневое упорядоченное дерево состоящее из двух деревьев latexmath:[B_{k-1}], связанных вместе, так что корень одного является крайним слева дочерним узлом другого. На <<fig:bcast_bmtrees,рис. 3.12>> приведены примеры четырех биномиальных деревьев B0, B1, B2 и B3. Количество дочерних узлов вершины логарифмически зависит от числа её потомков. Это принципиально отличает биномиальные деревья от latexmath:[k]-ичных, в которых степень узла фиксирована.

[.text-center]
.Рис. 3.12. Биномиальные деревья B0, B1, B2 и B3.
[[fig:bcast_bmtrees]]
image::bcast-bmtree.svg[width=40%]

Биномиальное дерево Bcast для latexmath:[p] процессов – это совокупность биномиальных деревьев, степени которых определяются номерами значащих битов в двоичном представлении числа latexmath:[p] процессов, участвующих в операции. Степени всех биномиальных деревьев различны. Например, при числе процессов latexmath:[p=8=1000_2] имеем одно биномиальное дерево latexmath:[B_3] (<<fig:bcast_bmtree,рис. 3.13>>).

Обозначим через latexmath:[i_1, i_2, \ldots, i_n] номера значащих битов в двоичном представлении числа latexmath:[p]

[latexmath]
++++
0 \le i_1 \le i_2 \le \ldots \le i_{n} \le \lfloor \log_{2}{p} \rfloor.
++++
Все биномиальные деревья объединены в единое дерево обменов, корнем которого является корень биномиального дерева latexmath:[B_{i_n}] – дерево наибольшей степени:

* самым левым дочерним узлом корня latexmath:[B_{i_n}] является корень дерева latexmath:[B_{i_{n-1}}];
* самым левым дочерним узлом latexmath:[B_{i_{n-1}}] является корень дерева latexmath:[B_{i_{n-2}}];
* latexmath:[\ldots]
* самым левым дочерним узлом корня latexmath:[B_{i_2}] является корень дерева latexmath:[B_{i_1}].

На <<fig:bcast_bmtree,рис. 3.13>> показано дерево обменов для latexmath:[p = 13=1101_2] процессов. Корнем всего дерева является дерево latexmath:[B_3], его самым левым дочерним узлом является корень дерева latexmath:[B_2]. В свою очередь, самым левым дочерним узлом дерева latexmath:[B_2] является корень дерева latexmath:[B_0] (корни деревьев обозначены двойной линией).

[.text-center]
[[fig:bcast_bmtree]]
.Рис. 3.13. Биномиальное дерево обменов операции Bcast: двойной линией обозначены корни биномиальных деревьев B3, B2 и B0: слева latexmath:[p = 8=1000_2], справа latexmath:[p = 13=1101_2]
image::bcast-bmtree.png[width=60%]

Биномиальное дерево обменов, в котором дочерние узлы с большими степенями находятся левее своих сестринских узлов, будем называть _левосторонним_. Заметим, что для операций корневой редукции (reduce, reduction) и сборки (gather) применяют правосторонние биномиальные деревья.

Корневой процесс выполняет latexmath:[\lceil \log_2 p \rceil] операций передачи сообщений. Каждый некорневой процесс latexmath:[r] выполняет один прием сообщения и не более latexmath:[\lfloor \log_2 r\rfloor] операций передачи. Процесс определяет свое положение в дереве (номера родительского процесса и дочерних) основываясь только на своем номере latexmath:[rank]. Номер latexmath:[parent] родительского процесса вычисляется путем сброса в значении latexmath:[rank] первого установленного бита (find first set – FFS). Наборы команд многих процессоров включают соответствующую инструкцию FFS или инструкцию CTZ (count trailing zeros) подсчета числа завершающих нулевых битов. В приложении приведен универсальный алгоритм CTZ. Тогда номер родительского процесса может быть вычислен следующим образом:

[latexmath]
++++
parent = rank \mathbin{\&} (\sim (1 \ll {CTZ}(rank))),
++++
или

[latexmath]
++++
parent = rank \mathbin{\textbf{xor}} ((1 \ll {FFS}(rank)) \gg 1).
++++
Например, для вычисления родителя процесса latexmath:[10 = 1010_2] сбрасываем второй бит и получаем номер родительского процесса latexmath:[parent = 8 = 1000_2]. Если реализация операций FFS и CTZ отсутствует, то поиск и установку необходимого бита можно реализовать последовательной проверкой в цикле разрядов числа latexmath:[rank].

Дочерние узлы каждого процесса имеют номера больше latexmath:[rank] и меньше latexmath:[p]. Они образуют следующую последовательность:

[latexmath]
++++
rank + 2^{{CTZ}(rank) - 1}, ~~rank + 2^{{CTZ}(rank) - 2}, ~~\ldots, ~~rank + 1.
++++
Количество дочерних узлов процесса latexmath:[rank] не превышает latexmath:[{CTZ}(rank)]. Справедливы следующие неравенства:

[latexmath]
++++
{CTZ}(rank) \le \log_2(rank) \le \log_2 p.
++++
Исключение составляет корневой процесс. Номера его дочерних узлов образуют убывающую последовательность степеней двойки от наибольшей степень числа два, которая меньше latexmath:[p], до единицы. Число дочерних узлов равно latexmath:[\lceil \log_2 p \rceil]. Для вычисления номера левого дочернего узла необходимо выполнить округление значения latexmath:[p - 1] до ближайшей снизу степени числа два. Последнее может быть реализована тривиальным циклическим алгоритмом или поразрядной операцией FLP2 (rounding down to next power of 2) <<bib-WarrenHackersDelight,[60]>> . Например, для latexmath:[p = 16] процессов первый дочерний узел корня имеет номер latexmath:[{FLP2}(15) = 8], а при latexmath:[p = 9] дочерним узлом корня является latexmath:[{FLP2}(8) = 4]. Таким образом, номера дочерних узлов корня образуют убывающую последовательность степеней двойки latexmath:[{FLP2}(p - 1), \ldots, 2, 1]. Например, на <<fig:bcast_bmtree_p13, рис. 3.14>> корень имеет четыре дочерних узла latexmath:[8, 4, 2, 1].

[[fig:bcast_bmtree_p13]]
.Рис. 3.13. Биномиальное дерево обменов операции Bcast: latexmath:[p = 13 = 1101_2], latexmath:[root = 0] (двойной линией обозначены корни деревьев B3, B2 и B0).
image::bcast-bmtree-p13.png[width=36%]

Выше мы рассмотрели основные шаги алгоритма для случая когда корнем операции является процесс 0. В приведенном ниже псевдокоде корнем операции может быть люой процесс. Это реализуется путем введения новой нумерации процессов, в которой корневой процесс всегда имеет виртуальный номер 0. Каждый процесс вычисляет свой _относительный номер_ latexmath:[srank] – номер процесса относительно корневого (relative rank, shifted rank):

[latexmath]
++++
srank = (rank - root + p) \mathbin{\%} p.
++++
Корневой процесс всегда имеет latexmath:[srank] равный нулю.

Перед выполнением обменов происходит обратный переход от относительных номеров процессов к исходным:

[latexmath]
++++
rank = (srank + root) \mathbin{\%} p.
++++

[source,c]
----
algorithm BcastBinomial(buf, count, type, root)
  srank = (rank - root + p) % p      // Переход к root = 0
  if srank > 0 then
    mask = (1 << FFS(srank)) >> 1
    // Сброс в srank первого установленного бита
    sparent = srank xor mask
    parent = (parent + root) % p
    Recv(buf, count, type, parent)  // Прием от родителя
  else
    mask = FLP2(p - 1) // Ближайшая снизу к p - 1 степень двойки
  end if
  while mask > 0 do
    schild = srank or mask
    if schild < p then
      child = (schild + root) % p
      Send(buf, count, type, child) // Передача дочерним
    end if
    mask = mask >> 2
  end while
end algorithm
----

Время работы алгоритма биномиального дерева определяется временем работы корневого процесса, которое складывается из времени передачи сообщений latexmath:[\left\lceil\log_2 p\right\rceil] дочерним узлам:

[latexmath]
++++
t_{{Binomial}} = \left\lceil\log_2 p\right\rceil (\alpha + m\beta).
++++
Время выполнения алгоритма совпадает с нижней границей Bcast по латентности – алгоритм биномиального дерева для сообщений небольших размеров является оптимальным (при небольших сообщениях вклад latexmath:[\alpha] в итоговое время доминирующий). Однако время его выполнения в latexmath:[\log_2 p] раз больше нижней границы Bcast по пропускной способности.

В алгоритме биномиального дерева номер процесса latexmath:[rank] трактуется как число в двоичной системе исчисления, обобщим алгоритм для случая системы исчисления с произвольным основанием latexmath:[k \in \{2, 3, \ldots, p - 1\}].

=== Алгоритм latexmath:[k]-номиального дерева

Процессы логически выстраиваются в дерево обменов, представляющее собой совокупность _latexmath:[k]-номиальных деревьев_ (latexmath:[k]-nomial tree). При latexmath:[k = 2] дерево называется _биномиальным_ (binomial tree), а при latexmath:[k = 3] – _триномиальным_ (trinomial tree). В англоязычной литературе можно встретить названия _quadnomial tree_ для latexmath:[k = 4] и _octanomial tree_ для latexmath:[k = 8]. В русскоязычной литературе эти термины не получили широкого распространения. На <<fig:bcast_knomial,рис. 3.15.а>> и <<fig:bcast_knomial,рис. 3.15.б>> показаны примеры организации 14 процессов в триномиальное и 4-номиальное деревья. При latexmath:[k=3] операция Bcast завершается за 5 шагов, а при latexmath:[k=4] за 6.

.Рис. 3.15.а. k-номиальное дерево операции Bcast для 14 процессов latexmath:[k=3]
image::bcast-kmtree-k3.svg[width=35%]

[.text-center]
[[fig:bcast_knomial-b]]
.Рис. 3.15.б. k-номиальное дерево операции Bcast для 14 процессов latexmath:[k=4]

Номера процессов трактуются как числа, записанные в системе счисления с основанием latexmath:[k] (radix, base). В каждом разряде номера процесса может стоять цифра из множества latexmath:[\{0, 1, \ldots, k - 1\}]. Например, номер процесса 12 в системах счисления с основаниями latexmath:[k \in \{3, 4\}] имеет следующие представления:

[latexmath]
++++
12 = 3^2 + 3^1 = 110_3, \quad 12 = 3\cdot4^1 + 4^0 = 30_4.
++++

_Номер родительского процесса_ вычисляется путем сброса в номере latexmath:[rank] текущего процесса самого младшего разряда с положительным весом (least significant digit). Например, в биномиальном дереве номер родителя для процесса latexmath:[rank=12=1100_2] равен latexmath:[8 = 1000_2], который получен путем сброса в числе 12 третьего бита (младшего значащего разряда). Аналогично, в триномиальном дереве родительским для процесса latexmath:[12 = 110_3] является узел latexmath:[9 = 100_3], а в 4-номиальном дереве родительским для процесса latexmath:[12=30_4] является процесс 0.

Поиск младшего ненулевого разряда может быть реализован специальными инструкциями процессора или универсальным алгоритмом на основе поиска в цикле младшего значащего разряда. Для этого в порядке возрастания перебираются степени числа latexmath:[k]:

[latexmath]
++++
k, ~k^2, ~k^3, ~\ldots, ~k^q < p.
++++
Если остаток от деления номера процесса latexmath:[rank] на latexmath:[k^i] больше нуля, то искомый разряд найден. Выполняется его сброс и прием сообщения от родительского процесса.

Количество _дочерних узлов_ любого процесса не превышает значения

[latexmath]
++++
(k-1)\left\lceil\log_k p\right\rceil.
++++
Пусть найденный младший значащий разряд в latexmath:[rank] соответствует степени latexmath:[k^q]. Тогда для нумерации дочерних узлов процесса latexmath:[rank] доступны его младшие нулевые разряды, соответствующие степеням

[latexmath]
++++
k^{q-1}, ~k^{q-2}, ~\ldots, ~1.
++++
Номер каждого дочернего узла образуется путем установления одного из младших нулевых разрядов. Заметим, что в любом из доступных latexmath:[q] разрядов может быть записана цифра из множества latexmath:[\{1, 2, \ldots, k-1\}]. Поэтому число дочерних процессов узла latexmath:[rank] не превышает latexmath:[(k-1)q]. Таким образом, у корневого процесса количество дочерних узлов не превышает значения latexmath:[(k-1)\left\lceil\log_k p\right\rceil].

Например, в биномиальном дереве для нумерации дочерних узлов процесса latexmath:[8=1000_2] доступно три младших разряда, которые соответствуют степеням latexmath:[2^2, 2^1, 1]. Таким образом процесс 8 имеет дочерние узлы с номерами:

[latexmath]
++++
12=8+4=1100_2, \quad 10=8+2=1100_2, \quad 9=8+1=1001_2.
++++
В 4-номиальном дереве в каждом разряде могут стоять цифры 0, 1, 2 и 3, потому процесс latexmath:[4=10_4] имеет дочерние узлы:

[latexmath]
++++
5=4+1\cdot1=11_4, \quad 6=4+2\cdot1 = 12_4, \quad 7=4+3\cdot1=13_4.
++++

В приведенном ниже псевдокоде номера дочерних узлов перебираются в цикле путем прохода по убыванию степеней числа latexmath:[k].

[source,c]
----
algorithm BcastKnomial(buf, count, type, root)
  srank = (rank - root + p) % p       // Переход к root = 0
  mask = 1
  while mask < p do
    if srank % (k * mask) > 0 then
      // Сброс разряда в srank
      sparent = floor(srank / (k * mask)) * (k * mask)
      parent = (sparent + root) % p
      Recv(buf, count, type, parent)  // Прием от родителя
      break
    end if
    mask = mask * k
  end while
  mask = mask / k
  while mask > 0 do
    for (r = 1; r < k; r = r + 1)
      schild = srank + mask * r
      if schild < p then
        child = (schild + root) % p
        Send(buf, count, type, child)
      end if
    end for
    mask = mask / k
  end while
end algorithm
----

Время работы алгоритма – это время корневого процесса на передачу сообщений latexmath:[(k-1)\left\lceil\log_k p\right\rceil] дочерним узлам:

[latexmath]
++++
t_{{Knomial}} = (k-1)\left\lceil\log_k p\right\rceil (\alpha + m\beta).
++++

На <<fig:bcast_kmtree-time,рис. 3.16>> приведена зависимость числа шагов алгоритма latexmath:[k]-номиального дерева от степени latexmath:[k]. Видно, что из дискретных значений latexmath:[k \in \{2, 3, \ldots p - 1\}] целесообразно выбирать latexmath:[k^{*}=2], при котором алгоритм выполняет наименьшее число шагов.

[[bcast_pipelined]]
=== Конвейерный алгоритм с сегментацией сообщения

В этом алгоритме процессы выстраиваются в цепочку, а исходное сообщение разбивается на latexmath:[\left\lceil\frac{m}{s}\right\rceil] сегментов по latexmath:[s] байт, latexmath:[s] – это входной параметр алгоритма. Корневой процесс передает сегмент за сегментом своему соседу. Каждый внутренний процесс цепочки принимает текущий сегмент и одновременно с этим передает ранее принятый (если такой имеется). На <<fig:bcast_pipeline_segs,рис. 3.17>> показан пример для четырех процессов и разбиения сообщения на три сегмента. Подразумеваться, что каналы связи поддерживают _дуплексный режим_ работы (full duplex) – каждый процесс может одновременно передавать и принимать сообщение. Это позволяет внутренним процессам цепочки выполнять операцию SendRecv за время latexmath:[\alpha + s\beta]. Если каналы связи _полудуплексные_ (half duplex), то время каждого внутреннего процесса увеличиться в два раза – приём текущего сегмента будет выполняться только после завершения передачи предыдущего (latexmath:[2(\alpha + s\beta)]). Следовательно и итоговое время работы алгоритма увеличиться в два раза.

.Рис. 3.17. Диаграмма выполнения конвейерного алгоритма для четырех процессов с разбиением сообщения на три сегмента (latexmath:[root = 0]).
[[fig:bcast_pipeline_segs]]
image::bcast-pipeline-segs.svg[width=44%]

Ниже приведен псевдокод, в котором latexmath:[count] элементов типа latexmath:[type] разбивается на latexmath:[\left\lceil\frac{m}{s}\right\rceil] сегментов. Каждый сегмент содержит latexmath:[s / \mathrm{sizeof}(type)] элементов типа latexmath:[type]. Все процессы в цикле выполняют прием и/или передачу сегментов. Размер сообщения может не делиться без остатка на latexmath:[s], поэтому последний сегмент может быть неполным. Для этого алгоритм вычисляет в переменной latexmath:[cur\_seg\_count] размер текущего сегмента.

[source,c]
----
algorithm BcastPipeline(buf, count, type, root)
  next = (rank + 1) % p
  prev = (rank - 1 + p) % p
  srank = (rank - root + p) % p

  // Число элементов типа type в сегменте
  seg_count = s / sizeof(type)
  nsegs = ceil(count / seg_count)
  if count < seg_count then
    // Сообщение меньше сегмента
    seg_count = count
  end if
  seg_size = seg_count * sizeof(type)
  cur_seg_count = seg_count

  if srank = 0 then                    // Корень операции
    for (seg = 0; seg < nsegs; seg++)
      if seg = nsegs - 1 and count % seg_count then
        // Последний сегмент может быть неполным
        cur_seg_count = count % seg_count
      end if
      Send(buf + seg * seg_size, cur_seg_count, next)
    end for
  else if srank = p - 1 then           // Последний процесс цепочки
    for (seg = 0; seg < nsegs; seg++)
      if seg = nsegs - 1 and count % seg_count then
        cur_seg_count = count % seg_count
      Recv(buf + seg * seg_size, cur_seg_count, prev)
    end for
  else                                 // Внутренний процесс
    Recv(buf, seg_count, type, prev)   // Прием первого сегмента
    for (seg = 1; seg < nsegs; seg++)
      if seg = nsegs - 1 and count % seg_count then
        cur_seg_count = count % seg_count
      SendRecv(buf + (seg - 1) * seg_size, seg_count, next,
               buf + seg * seg_size, cur_seg_count, prev)
    end for
    Send(buf + (nsegs - 1) * seg_size, cur_seg_count, next)
  end if
end algorithm
----

Время выполнения алгоритма определяется временем получения заключительного сегмента последним процессом цепочки

[latexmath]
++++
t_{{Pipeline}} = \left(p-1 + \frac{m}{s} - 1\right)\left(\alpha + s\beta\right).
++++
Из полученного выражения найдем оптимальный размер сегмента, при котором время алгоритма минимально (в рамках рассматриваемой модели):

[latexmath]
++++
\frac{\partial}{\partial s}\left( \left(p-1 + \frac{m}{s} - 1\right)\left(\alpha + s\beta\right) \right) = -\frac{m}{s^2}\alpha + (p-2)\beta = 0.
++++
Откуда

[latexmath]
++++
s^{*} = \sqrt{\frac{m\alpha}{(p-2)\beta}}.
++++

Нижняя кривая показывает нижнюю границу latexmath:[m\beta] времени операции Bcast для сообщений больших размеров. Видно, что при рассылке операцией Bcast сообщения меньше 3 МБ наименьшее время требуется алгоритму биномиального дерева, а для сообщений больших размеров лучшие результаты демонстрирует конвейерный алгоритм с оптимальным размером сегмента. На практике целесообразно провести серию экспериментов и определить наилучшее значение сегмента. Найденное значение latexmath:[s^{*}] является хорошим начальным приближением для такого поиска.

В этом алгоритме число операций Send/Recv линейно зависит от числа процессов и количества сегментов. Оценим во сколько раз алгоритм превышает нижнюю границу latexmath:[m\beta] времени Bcast по пропускной способности. Найдем множитель при latexmath:[\beta] в отношении latexmath:[t_{{Pipeline}}] к нижней границе latexmath:[m\beta]:

[latexmath]
++++
\frac{(p-1 + m/s - 1)s}{m} = \frac{p-1}{n} + \frac{n-1}{n},
++++
где latexmath:[n = \frac{m}{s}] – число сегментов. Видно, что при использовании одного сегмента latexmath:[n=1] отклонение от нижней границы по пропускной способности будет в latexmath:[p-1] раз. При числе сегментов latexmath:[n \geq p-1] отклонение от нижней границы становится меньше двух и убывает с ростом latexmath:[n].

И так для сообщений небольших размеров мы получили алгоритм биномиального дерева, а для больших сообщений – конвейерный алгоритм с сегментацией сообщений. Остался открытым вопрос о выборе алгоритма для сообщений средних размеров. Объединим идеи бинарного дерева и конвейерной передачи сегментов в следующем алгоритме.

=== Алгоритм бинарного дерева с сегментацией сообщения

Процессы выстраиваются в бинарное дерево. Исходное сообщение разбивается на latexmath:[\left\lceil\frac{m}{s}\right\rceil] сегментов по latexmath:[s] байт. Корень передает сегмент за сегментом своим левому и правому дочерним процессам. На <<fig:bcast_pipelined_bin_tree,рис. 3.19>> показан пример для 7 процессов и трёх сегментов сообщения. На первом шаге корень передает первый сегмент процессу 1, на втором шаге этот же сегмент передается процессу 2, после чего корень начинает передачу дочерним узлам второго фрагмента.

На третьем шаге процесс 1 одновременно передает первый сегмент и принимает второй – используется полнодуплексный режим (<<fig:bcast_pipelined_bin_tree_ops,рис. 3.20>>). На четвертом шаге в полнодуплексном режиме работает процесс 2. Таким образом полнодуплексный режим у процессов 1 и 2 используется не каждом шаге, а только через шаг, что не позволяет полностью использовать возможности каналов связи – достигнуть использования всей доступной пропускной способности (full bandwidth).

Время выполнения алгоритм определяется высотой дерева latexmath:[h]. Первый сегмент достигнет листа через latexmath:[h = \lceil\log_2 p \rceil] шагов. На прием оставшихся сегментов потребуется еще latexmath:[n - 1] шагов, где latexmath:[n = \left\lceil\frac{m}{s}\right\rceil] – число сегментов. Время выполнения алгоритма определяется временем получения последнего сегмента самым правым листом:

[latexmath]
++++
t_{{PipelinedBinTree}} = 2\left(h+\left\lceil\frac{m}{s}\right\rceil-1\right)(\alpha + s\beta) = 2\left(\lceil\log_2 p\rceil + \left\lceil\frac{m}{s}\right\rceil - 1\right)(\alpha + s\beta).
++++

Из выражения latexmath:[t_{{PipelinedBinTree}}] найдем оптимальный размер сегмента, при котором время алгоритма минимально:

[latexmath]
++++
\frac{\partial}{\partial s}\left(
        2\left( \log_2 p + \frac{m}{s} - 1\right)(\alpha + s\beta)
         \right) = -\frac{2m}{s^2}\alpha + 2(\log_2 p - 1)\beta = 0.
++++
Откуда

[latexmath]
++++
s^{*} = \sqrt{\frac{m\alpha}{(\log_2 p - 1)\beta}}.
++++

Алгоритм биномиального дерева показывает лучшие результаты для сообщений меньше 120КБ, для сообщений в интервале [120KB, 20MB] лучшие результаты у алгоритма бинарного дерева с сегментацией сообщения. Для сообщений больше 50МБ наименьшее время у конвейерного алгоритма с оптимальным размером latexmath:[s^{*}] сегмента. На практике можно провести измерения времени выполнения алгоритмов на целевой системе для различных latexmath:[p], latexmath:[m] и сформировать правило динамического выбора алгоритма с наименьшим временем для заданного числа процессов и размера сообщений.

=== Алгоритм на основе Scatter и Allgather

Рассмотрим два алгоритма Bcast для сообщений больших размеров, которые не используют конвейерную передачу сегментов. Их ключевая идея – это расщепление операции Bcast на две коллективные операции – Scatterv с последующим вызовом Allgatherv  <<bib-Barnett1994InterprocessorCC,[61]>> . Алгоритм имеет ограничение – он применим для больших размеров сообщений latexmath:[count \ge p].

Исходное сообщение разбивается на latexmath:[p] блоков по latexmath:[count / p] элементов типа latexmath:[type], которые рассылаются операцией Scatterv всем процессам. После чего все блоки собираются в каждом процессе операцией Allgatherv. Фаза Scatterv реализуется алгоритмом биномиального дерева, а операция Allgatherv алгоритмом рекурсивного удваивания (recursive doubling) или кольцевым алгоритмом. Рассмотрим подробнее версию с Allgatherv на базе кольца. Ниже приведен псевдокод алгоритма.

На этапе Scatterv корневой процесс передает каждому дочернему узлу блоки для его поддерева. На <<fig:bcast_scatterv_allgatherv,рис. 3.22>> показано биномиальное дерево, в котором процесс 4 принимает от корня блоки 4-7, процесс 2 блоки 2-3, а листовой процесс 1 только свой блок. Внутренние узлы дерева принимаю блоки и передают соответствующие части своим дочерним процессам. После окончания фазы Scatterv каждый процесс содержит в буфере latexmath:[buf] порядка latexmath:[count / p] элементов типа latexmath:[type] начиная с позиции latexmath:[srank] (новая нумерация процессов с корнем 0).

Каждый процесс поддерживает в переменной latexmath:[recv\_count] количество элементов, которые он получил от родителя для его поддерева. Обратим внимание, что стандарт MPI позволяет указывать в операции Recv большее число принимаемых элементов, чем в действительности может содержать входящее сообщение. Поэтому при приеме блоков от родителя мы указываем оценку сверху latexmath:[recv\_max] ожидаемого числа элементов. Это упрощает алгоритм. Реальное число принятых элементов определяется функцией GetRecvCount. На <<fig:bcast_allgatherv_ring,рис. 3.23>> приведен пример кольцевого алгоритма Allgatherv для 8 процессов.

[source,c]
----
algorithm BcastScatterAllgatherRing(buf, count, type, root)
  srank = (rank - root + p) % p
  block = ceil(count / p)
  mask = 1                       // Scatterv: прием блоков от родителя для поддерева
  while mask < p do
    if srank and mask then
      parent = (rank - mask + p) % p
      recv_max = count - srank * block
      if recv_max <= 0 then
        recv_count = 0
      else
        Recv(buf + srank * block * sizeof(type), recv_max, type, parent, status)
        recv_count = GetRecvCount(status, type) // Число принятых элементов типа type
      end if
      break
     end if
     mask = mask * 2
  end while
  mask = mask / 2                               // Scatterv: биномиальное дерево
  if rank = root then recv_count = count
  while mask > 0 do
    if srank + mask < p then
      send_count = recv_count - block * mask
      if send_count > 0 then
        child = (rank + mask) % p
        Send(buf + block * (srank + mask) * sizeof(type),
             send_count, type, child)
        recv_count = recv_count - send_count
      end if
    end if
    mask = mask / 2
  end while

  // Allgatherv: кольцевой алгоритм
  left = (rank - 1 + p) % p
  right = (rank + 1) % p
  send_block = srank
  recv_block = (srank - 1 + p) % p
  for (i = 1; i < p; i = i + 1)
    recv_count = min(block, count - recv_block * block)
    if recv_count < 0 then recv_count = 0
    recv_offset = recv_block * block * sizeof(type)
    send_count = min(block, count - send_block * block)
    if send_count < 0 then send_count = 0
    send_offset = send_block * block * sizeof(type)
    SendRecv(buf + send_offset, send_count, type, right,
             buf + recv_offset, recv_count, type, left)
    send_block = recv_block
    recv_block = (recv_block - 1 + p) % p
  end for
end algorithm
----

Читателю предлагается самостоятельно разобрать случай когда latexmath:[count] не делится без остатка на latexmath:[p] – выяснить как по дочерним процессам распределяются блоки.

Оценим время выполнения алгоритма. Время алгоритма биномиального дерева для Scatterv определяется временем корня, который последовательно за latexmath:[\left\lceil\log_2p\right\rceil] итераций передает своим дочерним процессам группы со следующим количеством блоков:

[latexmath]
++++
2^{\log_2p - 1}, \quad 2^{\log_2p - 2}, \quad \ldots, \quad 2^2, \quad 2^1, \quad 1.
++++
Каждый блок по latexmath:[count / p] элементов типа latexmath:[type] и занимает latexmath:[m/p] байт. Тогда время этапа Scatterv:

[latexmath]
++++
t_{{Scatterv}} = \log_2p\alpha + \frac{m}{p}\left(1 + 2^1 + 2^2 + \ldots + 2^{\log_2p - 1}\right)\beta = \log_2p\alpha + \frac{(p-1)m}{p}\beta.
++++
На этапе Allgatherv все процессы выполняют одинаковое число шагов. В случае использования кольцевого алгоритма каждый процесс выполняет latexmath:[p-1] операций SendRecv блоками по latexmath:[m/p] байт:

[latexmath]
++++
t_{{AllgathervRing}} = (p-1)\alpha + \frac{(p-1)m}{p}\beta.
++++
Здесь предполагается, что каналы связи поддерживают дуплексный режим – операции Send и Recv выполняются одновременно. Итоговое время алгоритма Bcast на основе Scatterv с биномиальным деревом и операцией Allgatherv на базе кольца:

[latexmath]
++++
t_{{ScattervAllgathervRing}} = \left(\log_2p + p - 1\right)\alpha + 2\frac{(p-1)m}{p}\beta.
++++

В случае реализации Allgatherv рекурсивным удваиванием каждый процесс выполняет latexmath:[\log_2 p] операций SendRecv группами блоков возрастающей длины:

[latexmath]
++++
1, \quad 2,\quad 4, \quad \ldots, \quad 2^{\log_2p - 1}.
++++
Время выполнения Bcast в этом случае составит:

[latexmath]
++++
t_{{ScattervAllgathervRdbl}} = 2\log_2 p\alpha + 2\frac{(p-1)m}{p}\beta.
++++

На <<fig:bcast_scatter_allgather_time,рис. 3.24>> приведено время выполнения алгоритмов операции Bcast на модельных данных. На размерах сообщений до 30КБ лучшие результаты показывает алгоритм биномиального дерева. На сообщениях [30КБ, 70МБ] наименьшее время у алгоритма ScattervAllgathervRdbl, а на сообщениях больше 70MB лучшие результаты показывает конвейерный алгоритм с оптимальным размером сегмента.

=== Алгоритмы оптимальные по пропускной способности

Возможно ли построить алгоритм операции Bcast, который будет достигать нижней границы времени Bcast для больших сообщений (full bandwidth algorithm)? Ответ утвердительный. Известно несколько алгоритмов, например <<bib-Sanders2009-two-tree,[28]>> , <<bib-TRAFF2008887,[62]>> , но они требуют предварительных вычислений позиции процессов в графах и деревьях специального вида. В <<bib-TRAFF2008887,[62]>> предлагается использовать циркулянтный граф, а главная идея <<bib-Sanders2009-two-tree,[28]>> – построить два бинарных дерева, в которые входит каждый процесс и на каждом шаге выполняет одновременный прием и передачу сегментов.

=== Операция Scatter

Операция Scatter – это персонифицированная широковещательная рассылка. Все процессы получают сообщения одинакового размера, но из разных позиций буфера отправки latexmath:[sbuf], который содержит latexmath:[p] блоков:

----
MPI_Scatter(sbuf, scount, stype, rbuf, rcount, rtype, root, comm)
----

Корневой процесс latexmath:[root] передает latexmath:[scount] элементов типа latexmath:[stype] каждому процессу latexmath:[rank] начиная с адреса

[latexmath]
++++
sbuf + rank \cdot scount \cdot \mathrm{sizeof}(stype).
++++
Процессы принимают сообщение в буфер latexmath:[rbuf] как latexmath:[rcount] элементов типа latexmath:[rtype]. Тип принимаемых элементов latexmath:[rtype] может отличаться от типа отправляемых latexmath:[stype]. Например, корень может отправить каждому процессу персональную строку матрицы из 100 целых чисел, а принимающий процесс может сохранить сообщение в памяти как столбец из 100 элементов. Требования стандарта выполнены, сигнатуры типа отправки latexmath:[stype] (MPI type signature) и приема latexmath:[rtype] совпадают, совпадает и их размер – 100 элементов типа . Параметры latexmath:[sbuf], latexmath:[scount] и latexmath:[stype] значимы только на стороне корня, остальным процессам следует их игнорировать.

Стандарт MPI определяет операцию Scatterv c нерегулярными размерами сообщений.

----
MPI_Scatterv(sbuf, scounts[p], displs[p], stype, rbuf, rcount, rtype, int root, comm)
----

Корень передает процессу latexmath:[rank] сообщение из latexmath:[scounts[rank]] элементов типа latexmath:[stype] начиная со смещения

[latexmath]
++++
sbuf + displs[rank] \cdot \mathrm{sizeof}(stype).
++++

Для операции Scatter мы рассмотрим два основных алгоритма её реализации – линейный и алгоритм биномиального дерева. Для нерегулярной версии Scatterv, как правило, библиотеки реализуют только линейный алгоритм. Мы не будем его рассматривать, так как он аналогичен соответствующему алгоритму для Scatter.

==== Линейный алгоритм

Ниже приведен псевдокод _линейного_ алгоритма (linear, flat tree) для Scatter. Корневой процесс выполняет latexmath:[p] операций Send, включая передачу самому себе – копирование из своего буфера latexmath:[sbuf] в latexmath:[rbuf]. Время выполнения алгоритма

[latexmath]
++++
t_{{Linear}} = p(\alpha + m\beta).
++++

[source,c]
----
algorithm ScatterLinear(sbuf, scount, stype, rbuf, rcount, rtype, root, comm)
  if rank = root then
    for (i = 0; i < p; i++)
      if i = root then
        SendRecv(sbuf + i * scount * sizeof(stype), scount, stype, i,
                 rbuf, rcount, rtype, i)
      else
        Send(sbuf + i * scount * sizeof(stype), scount, stype, i)
      end if
    end for
  else
    Recv(rbuf, rcount, rtype, root)
  end if
end algorithm
----

[[алгоритм-биномиального-дерева]]
==== Алгоритм биномиального дерева

Теперь рассмотрим алгоритм _биномиального дерева_. Корнем дерева может быть процесс отличный от нуля, поэтому в начале вводится новая нумерация, в которой корень имеет latexmath:[srank = 0]. Это упрощает вычисление номера родительского узла и дочерних. Внутренним процессам дерева требуется временный буфер для приема сообщения от родителя.

[.text-center]
.Рис. 3.25. Алгоритм биномиального дерева для операции Scatter (latexmath:[p=8], latexmath:[root=0], в квадратных скобках показан диапазон передаваемых сообщений).
[[fig:scatter_bmtree]]
image::bcast-scatterv-bmtree.svg[width=20%]

Размер буфер не превышает latexmath:[m\cdot p / 2] байт – суммарный размер сообщений для потомков любого поддерева. Если корневым является ненулевой процесс, то он выполняет перестановку элементов во временном буфере latexmath:[tmpbuf] так, чтобы элементы в нем следовали в соответствии с новой нумерацией: latexmath:[[root, root + 1, \ldots, (root - 1 + p) \mathbin{\%} p]]. Листовые процессы принимают сообщение сразу в буфер latexmath:[rbuf]. Внутренние процессы принимают и передают сообщения в свои поддеревья использую тип . Это связно с тем, что у некорневых процессов отсутствует информация о типе данных корня, параметры latexmath:[scount] и latexmath:[stype] значимы только в корневом процессе. Кроме этого, использование позволяет не тратить время на разворачивание в памяти сообщений в соответствии с сигнатурой типа latexmath:[rtype]. Детали формирования структуры дерева приведены в <<bcast_bmtree,разделе 3.7>>. В переменной latexmath:[cur\_count] поддерживается суммарный размер сообщений, которые хранятся в буфере процесса latexmath:[sbuf] (если latexmath:[root = 0]) или буфере latexmath:[rbuf] при latexmath:[root > 0]. Ниже приведен псевдокод алгоритма.

[source,c]
----
algorithm ScatterBinomial(sbuf, scount, stype, rbuf, rcount, rtype, root, comm)
  srank = (rank - root + p) % p      // Переход к root = 0
  if rank = root then
    m = scount * sizeof(stype)
  else
    m = rcount * sizeof(rtype)
  end if
  cur_count = 0

  if (rank != root) and (srank % 2 = 0) then
    tmpbuf = AllocMem(m * p / 2) // Временный буфер для внутренних узлов дерева
  end if
  if rank = root then
    if root != 0 then
      tmpbuf = AllocMem(m * p)
      // Перестановка элементов в tmpbuf
      Copy(sbuf + rank * scount * sizeof(stype),
           scount * (p - rank), stype, tmpbuf, m * (p - rank))
      Copy(sbuf, rank * scount, stype, tmpbuf + m * (p - rank), rank * m)
      cur_count = m * p
    else
      cur_count = scount * p
    end if
  end if
  mask = 1
  while mask < p do                        // Приём от родителя
    if srank and mask then
      parent = (rank - mask + p) % p
      if srank % 2 then
        Recv(rbuf, rcount, rtype, parent)  // Лист в дереве
      else
        Recv(tmpbuf, m * p / 2, MPI_BYTE, parent, status)
        cur_count = GetRecvCount(status, MPI_BYTE)
      end if
      break
    end if
    mask = mask * 2
  end while
  mask = mask / 2
  while mask > 0 do                        // Передача дочерним
    if srank + mask < p then
      child = (rank + mask) % p
      if (rank = root) and (root = 0) then
        subtree_count = cur_count - scount * mask
        Send(sbuf + mask * scount * sizeof(stype), subtree_count, stype, child)
      else
        subtree_count = cur_count - m * mask
        Send(tmpbuf + m * mask, subtree_count, MPI_BYTE, child)
      end if
      cur_count = cur_count - subtree_count
    end if
    mask = mask / 2
  end while
  // Копирование своего сообщения в rbuf
  if (rank = root) and (root = 0) then
    Copy(sbuf, scount, stype, rbuf, rcount, rtype)
  else if srank % 2 = 0 then
    Copy(tmpbuf, m, MPI_BYTE, rbuf, rcount, rtype)
  end if
end algorithm
----

Время алгоритма биномиального дерева для операции Scatter определяется временем корня, который последовательно за latexmath:[\left\lceil\log_2p\right\rceil] итераций передает своим дочерним процессам сообщения для их поддеревьев (потомков). Суммарные размеры сообщений, передаваемые корнем дочерним узлам образуют последовательность:

[latexmath]
++++
m2^{\log_2p - 1}, \quad m2^{\log_2p - 2}, \quad \ldots, \quad m2^2, \quad m2^1, \quad m.
++++
Тогда время выполнения алгоритма:

[latexmath]
++++
t_{{Binomial}} = \log_2p\alpha + \frac{m}{p}\left(1 + 2^1 + 2^2 + \ldots + 2^{\log_2p - 1}\right)\beta = \log_2p\alpha + \frac{(p-1)m}{p}\beta.
++++
